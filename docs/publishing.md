# 文档发布与回滚

## 当前与目标

当前正式网站由 GitBook 托管，GitBook 合并可能直接更新线上。历史版本存在 GitHub 同步记录；
GitBook 站点概览当前显示未连接，是否仍存在组织级 App 安装授权需 `BabelTTS` 核实。
此 PR 只引入仓库检查及流程规范，不改变任何 GitBook、GitHub、DNS 或 CDN 设置。

目标是：草稿 → GitHub PR → Alice 复核/安全检查 → Alice 合并与发布 → 线上复核。
若需要防止 GitBook 平台失陷后直接篡改页面，必须把正式页面交付改为独立静态站/CDN，
GitBook 只做草稿编辑入口，不持有生产部署或全局 DNS 凭据。目前未建设该部署工程，不得声称已完成。

## 维护分工

| 人员 | 职责与权限 |
| --- | --- |
| 内容编辑者 | 准备内容和依据，提交 PR，由 Alice 复核 |
| `aliceChuhT`（Alice） | 唯一日常维护者，具备仓库 Write 及对应 GitBook 发布权限；自行复核、合并、发布和回滚，必要时向研发核实敏感内容 |
| `BabelTTS` | 一次性配置 GitHub 授权、Actions 和分支保护，协调 GitBook 管理员完成对应授权；不作为日常审核、合并或发布必经人 |

`CODEOWNERS` 仅列出 Alice，标记维护责任。PR 的必需审批人数为 0，不启用强制 Code Owner 审核或
最新提交需他人批准；不依赖 `tabufan` 的 Write 权限，也不要求领导逐次审批。
单人模式保留 PR 记录和 CI 门禁，但不提供双人复核，不能防止 Alice 账号失陷后修改校验规则。
GitHub 权限与 GitBook 权限分别授权，不能凭其中一端的身份推断另一端权限。

## 每次内容发布

1. 建 PR，说明用户可见变化和依据。Alice 复核完整差异；地址、链、资金操作入口、安装命令和审计附件对照部署记录或官方来源核实，必要时咨询研发；产品行为变化向产品核实。
2. 敏感内容先走 [基线复核](document-security.md)，本地与 PR 检查通过。Alice 同时复核正文、Markdown 输出和附件，而不只看绿色状态。
3. 平台保护启用后，Alice 将复核完成且检查通过的 PR 合入 `master`，不需要他人 Approve 或 `BabelTTS` 审批。此仓库没有自动部署工作流；PR 合并不作为线上发布成功证据。
4. 独立发布尚未落地期间，由具备 GitBook 发布权限的日常维护者确认 GitHub 审核版本与 GitBook 待发布差异完全一致再发布。不得通过 GitBook 或 App 同步直接写入受保护主分支；必要时暂停现有同步并采用审核后的人工发布。
5. 发布后打开无登录状态的正式页面，验证关键入口、对应网络的地址、Markdown 输出和审计附件；确认无新增脚本/跳转。对关键 PDF 对照已审核哈希。
6. 在 PR 留存：源码提交、GitBook 变更/版本链接、发布人及时间、验证 URL 与结果、上一个可回滚版本。不得把凭据写入发布记录。

## 独立发布落地条件（维护者与运维实施）

- 明确静态站生成器、构建锁文件、托管服务、回滚命令及维护人，并在新部署 PR 中补齐实际命令。
- 草稿变更只进入候选分支，关闭所有绕过 GitHub PR 和安全检查的正式站点更新通道。
- 构建不带生产 Secrets；发布使用独立环境、合入受保护主分支后才可用的最小权限凭据，优先评估短期身份认证。
- 文档 Runner 不得接触业务生产网络、钱包或业务部署凭据；部署身份只能更新文档站。
- 域名切换、访问可用性、缓存与回滚演练完成后，才能把 GitBook 直接发布通道停用标记为已完成。
- 未来自动发布由受保护的合并触发；需要手动发布时由 Alice 执行，不添加另一人或领导的必需部署审批。

## 回滚与应急

- 发现错误地址、异常外链或脚本时，先保存异常内容、版本和时间，暂停发布及可疑同步。
- 源码用 revert PR 回到已审核版本，执行相同校验；不强推、不改写审计历史。
- 当前 GitBook 托管模式，由指定发布人恢复到对应已审核 GitBook 版本并复核线上；GitHub revert 不保证网页自动恢复。
- 怀疑 GitBook 平台本身失陷时，其历史和恢复按钮不是独立可信证据；对照仓库及离线副本验证，
  必要时由运维启用可信静态备份或维护页。恢复域名/CDN 的具体动作须按当次故障授权执行。
- 保存恢复证据；若 Token/Secrets 曾暴露，在各自发行端撤销和轮换，验证旧凭据失效后再恢复集成。
- 本次事件的日志复核、凭据排查、GitBook 权限整改及独立发布建设由 Alice、研发和运维承担；
  组织审计日志等仅 Owner 可访问的资料，由 `BabelTTS` 一次性导出或配置合适的读取权限后交团队排查。
